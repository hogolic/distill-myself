## 三、核心一：PARA 骨架

### 先说 PARA 是什么

**PARA** 是 Tiago Forte 在《Building a Second Brain》里提出的四类分类法（四个并列的类别，不是层级）。四个字母：

| 字母 | 全称 | 中文 | 一句话 |
|---|---|---|---|
| **P** | **P**rojects | 项目 | **有终点**的事 |
| **A** | **A**reas | 领域 | **没终点**、要一直维持的事 |
| **R** | **R**esources | 资源 | 备查的知识和资料 |
| **A** | **A**rchives | 归档 | 已结束或暂停的 |

**它的核心洞察**：大多数人按「**主题**」分类（英语 / 健身 / 工作），结果是**永远不知道该往哪放** ——
因为一件事常常同时属于好几个主题。

**PARA 按「这件事的状态」分**：正在做？要长期维持？还是备查？
按状态分，**每个东西只有一个答案**。

---

### 逐个说清（这是最容易搞混的地方）

#### P — Projects｜项目

**有明确终点的事。** 做完会"结项"。

| | |
|---|---|
| ✅ | 「做一个抽帧工具」—— 做完就结束 |
| ✅ | 「备考 12 月英语考试」—— 考完就结束 |
| ❌ | 「英语」—— 这个不会结束，不算项目 |

**判据：你能说出"什么时候算做完"吗？** 能 → 是项目。

#### A — Areas｜领域

**没有终点、需要一直维持的事。** 它永远不会"做完"。

| | |
|---|---|
| ✅ | 「英语」—— 一直要练 |
| ✅ | 「身体与健身」—— 一直要维持 |
| ✅ | 「技术能力」—— 一直在长 |
| ❌ | 「做完这个网站」—— 那个有终点 |

**判据：你无法说出"什么时候算做完"。**

> 🔑 **P 和 A 怎么分？只问一句：这件事有终点吗？**
>
> 最容易混的一个：「备考英语考试」是 **P**（考完就结束），但它**服务于**「英语」这个 **A**。
> **P 可以结束，A 不会。**

#### R — Resources｜资源 → 我改成了 Knowledge

**原版**指"以后可能用上的参考资料"。

**我改成了 `30-知识 Knowledge`**，因为 Resources 太宽泛、界线不清 —— 几乎什么都能叫"资源"，
结果就是**什么都往里塞，然后找不到**。

改后的判据：**「你学明白了什么」** —— 别人的原文 + 你自己的理解。

| | |
|---|---|
| ✅ | 「高位下拉宽握更偏向背阔肌外侧」—— 一个知识点 |
| ✅ | 一篇书摘 + 你的批注 |
| ❌ | 「英语」—— 那是你要**维持**的（Areas），不是学明白的知识点 |

> **改了名字，本质没变**：还是"备查的东西"，只是把界线画清楚了。

#### A — Archives｜归档

**已结束或暂停的。** 从上面三处移过来。

**关键：移过来，不要删。** 归档的东西是以后回顾的素材 ——
尤其那些"当时觉得没用、后来发现有用"的。

---

### 完整判据（照着走就行）

```
这件事有终点吗？
├─ 有 ────────────────────────→ Projects（10-项目）
└─ 没有
   ├─ 是要「一直维持」的事？ ──→ Areas（20-领域）
   └─ 是「学明白的知识」？  ──→ Knowledge（30-知识）

特殊通道：
· 拿不准放哪 ────────────────→ Inbox（00-收件箱）
· 按时间记的（日记/反思）────→ Journal（40-日记）
· 已经结束 / 暂停 ───────────→ Archive（99-归档）
· 工具类（模板 / 附件）──────→ Templates / Attachments
· 关于「我」本人 ────────────→ 100-我自己 Myself（见下一节）
```

**关于三个特殊目录：**

- **Inbox** —— 什么都拿不准就先扔这儿。**整个库里只有这一个地方允许乱**
- **Journal** —— 按时间记，**不进分类体系**。日记不需要被分类，它按日期排就够
- **Archive** —— 结束了移过来。**不要删**

---

### 常见误用（避开这四条）

| 误用 | 后果 | 正确做法 |
|---|---|---|
| **什么都往 Areas 塞** | Areas 变成第二个收件箱，永远找不到东西 | 有终点的进 Projects；知识点进 Knowledge |
| **建十几个目录** | 每次分类要纠结一分钟，最后懒得记 | **先只建 4 个**，让目录自己长出来 |
| **Projects 永不结项** | 半成品越积越多，Projects 变成垃圾场 | 做完就移进 Archive |
| **把 PARA 当"文件夹分类法"** | 只学了形式，用起来还是纠结 | PARA 分的是**状态**，不是**主题** |

> **最后一条最重要。** 如果你按主题分，迟早会纠结"这个既像英语又像工作"。
> 按状态分，每个东西只有一个答案。

## 四、核心二：给「我自己」单独开一个目录

这是我做的最反常规的一件事。

PARA 的八个目录是按「**事情的性质**」分的。但我加了一个 `100-我自己 Myself`，它不按性质分，它按「**关于谁**」分。

> **PARA 回答「这东西放哪」，`100-我自己 Myself` 回答「我是谁」。**
> 前者是仓库，后者是镜子。PARA 管你收集的东西，Myself 管收集东西的你。

**为什么编号用 100 而不是 50？** 因为它排在 99 之后，视觉上一眼能看出**它不是 PARA 的成员**，是另一条轴。

里面放四样：

| 文件 | 是什么 |
|---|---|
| 关于我 · 个人说明书与成长档案 | **主档案** —— 想法与成长 |
| 人生档案 · 从小学到高中 | 经历叙事 |
| 我的个人信息 | 事实、配置、进度 |
| 他人视角/ | 各 AI 怎么看我 —— **各自独立成篇，不合并** |

**最后一条很重要**：不要让几个 AI 的观察合成一份"权威档案"。它们看到的侧面不同，**合成一份会丢掉差异，而差异才是信息。**

## 五、核心三：怎么把 AI 对话蒸馏成档案

这是整个方法里最值钱的部分。

### 做法

1. **正常和 AI 聊**，不刻意。想到什么聊什么
2. **聊到某件事聊透了**，让 AI 输出一份整理：**保留你的原话，把 AI 的分析标注为"假设"**
3. **这份整理进库**，作为档案的一份来源
4. **每次聊都追加**，不要覆盖旧的

### 三条铁律

**① 分清「你说的话」和「AI 的推断」**

好的整理长这样：

> **用户原话**：「我觉得可以走了，差不多去干点正事了。」
>
> **AI 的讨论假设（未证实）**：可能倾向于把学习视为"正事"，把欣赏景色视为可享受但不能占太多时间的活动。

**AI 的分析永远标成假设，不标成事实。** 否则三个月后你会把自己的推断当成自己的性格。

**② 不完整就留不完整**

> 「当时我隐约觉得被看不起；**这是一种当时的感受，并不能确定老师的真实意图**。」

**这比"老师看不起我"诚实得多**，也比"我记不清了"有用得多。

**③ 不让 AI 替你下结论**

可以让 AI 整理、提问、指出矛盾。**但"我到底怎么想"必须是你自己写的。**

### 这个动作的产出

聊十次，你会得到十份档案。它们不会自己合并 —— **那是对的**。你的想法本来就在变，**留十个版本比强行总结成一个更真实。**

## 六、核心四：让 AI 能维护，只要两份文档

这是让"AI 能进来干活"的关键。

**规则只有两份**（我一开始写了四份，后来砍到两份）：

| 文件 | 给谁看 | 讲什么 |
|---|---|---|
| `README.md` | 人和 AI | 这个库是什么、东西放哪、笔记怎么写 |
| `AGENTS.md` | **AI** | 干活要守什么规矩 |

**为什么砍到两份**：规则一分散，就没人守。四份文档的结果是**每份都被忽略一点**。

### AGENTS.md 里最重要的是什么

不是"怎么写笔记"，是**下面这几条硬规矩**：

```markdown
## 🔴 第一条铁律：能增、能改、能移，不能删

| 动作 | 权限 |
|---|---|
| 新建、修改、移动、重命名 | ✅ 可以直接做 |
| 删除 | ❌ 不行。要"删掉"的东西移到 99-归档 Archive/ |

为什么这条排第一：增、改、移都能回滚（git 有记录），删除不能。
```

**给 AI 权限，但要留余地。** 我给它的原话是：

> **「我想把你们当伙伴」—— 可以增加、修改、拖动文件，但不能删除。**

结果：它连"重复文件"都不删了，会问我"这个要不要归档"。

### 还有几条必须写进去

- **不要建空壳笔记** —— 否则库会变成 AI 生成内容的垃圾场
- **不要一次建一堆目录和索引** —— 过度设计比不做更糟
- **拿不准就扔 Inbox** —— 别硬塞
- **只有我能判断"什么值得留"** —— 归类可以代劳，价值判断不行

## 七、我踩过的 7 个坑

每一条都真花过时间。你可以直接跳过。

| # | 坑 | 怎么解决 |
|---|---|---|
| 1 | **把源码 clone 进库** | 一个项目 208 个文件 / 5.5MB，工作区从 500KB 涨到 19MB，网盘全同步到手机。**只记 GitHub 地址 + commit 号，别拷源码** |
| 2 | **Obsidian 开着时改文件** | 编辑器会把旧内容存回去，真的丢过 64 行。**改完必须 `git diff` 看一眼** |
| 3 | **看到大段删除就"恢复"** | 可能是我自己主动删的（判断变了）。**先问「谁删的」，别急着恢复** |
| 4 | **建了 34 个"待建主题"的空链接** | 好看但没用。**要写就从中间挑一个真想的，别一次全建** |
| 5 | **写了 12 条"台账/日志"机制** | 每次提交多改一个文件，还制造"文件没改却显示已修改"的噪音。**`git log` 本身就是台账，不用另做** |
| 6 | **规则写到四份文档** | 结果哪份都没被完整遵守。**收到两份，一份讲结构、一份讲规矩** |
| 7 | **让 AI 批量改元数据** | 57 个文件被加标签，导致真改动全被淹没。**元数据改动单独提交** |

**共同点**：**都是在做加法（加目录、加机制、加规则）之后，被迫做减法。**

**如果你只记住一句**：**先搭骨架，然后靠每天用，别一次设计完。** 上面七个坑里有五个是我"设计过度"造成的。

## 八、30 分钟复刻

### 第 1 步：装 Obsidian，建一个空文件夹

名字随便，放哪都行。**不要一上来就建九个目录。**

> ✅ **做对了**：Obsidian 里「打开文件夹作为仓库」，选到那个空文件夹，能打开。

### 第 2 步：只建四个目录

**名字必须和第一节的树一致**（数字 + 中文 + 空格 + 英文）：

```
00-收件箱 Inbox/
20-领域 Areas/
40-日记 Journal/
90-模板 Templates/
```

**够用了。** Projects 和 Archive 等你真的有了再加。

> ⚠️ **数字前缀必须两位以上**，否则 `10-` 会排在 `9-` 前面。
> 而且排序就是这个库唯一的"导航系统" —— 别省。

> ✅ **做对了**：侧边栏里四个目录按 00 → 20 → 40 → 90 的顺序排列。

### 第 3 步：复制三个模板，并在 Obsidian 里配置

把 `templates/` 里那三个文件放进库的 `90-模板 Templates/`：

| 模板 | 用途 |
|---|---|
| `笔记模板.md` | 通用 |
| `日记模板.md` | 四节：开心 / 不开心 / 所思所想 / **和 AI 聊完之后的总结** |
| `资料模板.md` | 外部资料，重点是「用自己的话讲一遍」 |

**然后在 Obsidian 里设三个地方**（设置 → 选项）：

1. **核心插件 → 模板** → 模板文件夹 = `90-模板 Templates`
2. **核心插件 → 日记** → 新建日记的存放位置 = `40-日记 Journal`
3. **文件与链接** → 新附件的默认位置 = `91-附件 Attachments`

> ✅ **做对了**：按 `Ctrl+P` 输入「插入模板」，能选到那三个；
> 点「打开今天的日记」，会在 `40-日记 Journal/` 里建出 `YYYY-MM-DD.md`。

> ⚠️ 模板里的 `{{date:YYYY-MM-DD}}` 是 **Obsidian 模板语法**，只有在模板插件启用时才生效。
> 用记事本直接打开会看到原样的占位符 —— **那是正常的，不是坏了**。

### 第 4 步：写你的 `README.md`

照 `boilerplate/README.md` 改。**只改三处**：你是谁、你的 Areas 有哪些、你的命名习惯。

**README 里必须包含 front matter 规范**（下面这份直接抄）：

```yaml
---
title: 一句话说清这篇讲什么
tags: [标签1, 标签2]
source: 外部资料必填出处；自己写的留空
created: YYYY-MM-DD
status: 草稿 | 待核对 | 已整理
---
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 一句话说清这篇讲什么 |
| `tags` | ✅ | 2-5 个，**超过 5 个等于没打** |
| `source` | ➖ | 外部资料必填；自己写的留空 |
| `created` | ✅ | `YYYY-MM-DD` |
| `status` | ✅ | 三选一：`草稿` / `待核对` / `已整理` |

> **`status` 是这套系统里最实用的一格。** 它让你一眼筛出"没写完的"和"需要我过目的"。

> ✅ **做对了**：README 里有目录结构表、front matter 表、命名规则、日常工作流四块。

### 第 5 步：写你的 `AGENTS.md`

照 `boilerplate/AGENTS.md` 改。**必须保留下面这条，一个字都别删**：

> ## 🔴 第一条铁律
> **可以增加文件、修改文件、移动文件 —— 但不能删除文件。**
> 需要"删掉"的东西 → **移到 `99-归档 Archive/`**

**为什么这条排第一**：增、改、移都能回滚（git 有记录），**删除不能**。

> ✅ **做对了**：`AGENTS.md` 第一条是删除限制，且"不要做的事"里至少写了
> 「不建空壳笔记」「不过度设计」两条。

### 第 6 步：装 git，做第一次提交

```bash
cd 你的库路径
git init
git add -A
git commit -m "init: 第二大脑骨架"
```

**为什么一定要 git**：它是唯一能"回到过去"的东西。**没有 git 的知识库，删错了就真没了。**

> ✅ **做对了**：`git log --oneline` 能看到一条 `init:` 开头的提交。

### 第 7 步：今天就开始写日记

**这是唯一不能跳的一步。**

不需要写完四节，写一行也行。**这个库会不会活，取决于你明天还写不写。**

> ✅ **做对了**：`40-日记 Journal/` 里有今天那个 `YYYY-MM-DD.md`，且至少有一行不是你从模板复制的。

## 做完之后逐条确认

**给 agent 的自检清单**（全部打勾才算完成）：

- [ ] 顶级目录 ≤ 5 个（超过就是过度设计，砍掉）
- [ ] 目录名是"数字 + 中文 + 空格 + 英文"，且数字两位数
- [ ] `README.md` 里有：目录结构表 / front matter 表 / 命名规则 / 日常工作流
- [ ] `AGENTS.md` **第一条是删除限制**
- [ ] `AGENTS.md` 写了「不建空壳笔记」「不过度设计」
- [ ] `90-模板 Templates/` 里至少两个模板，且 Obsidian 里配置好了模板文件夹
- [ ] Obsidian 里配置好了日记文件夹（`40-日记 Journal`）和附件文件夹（`91-附件 Attachments`）
- [ ] git 已初始化，有第一次提交
- [ ] 用户今天写了一条日记（哪怕一行）
- [ ] **库里没有任何空壳笔记**（0 字节的文件补上内容，或移到 `99-归档 Archive/` —— **不许删**）

## 进阶一：我已经有一堆笔记，怎么搬进来

> 这一节给「看到视频时手头已经有一堆散落笔记」的人。
> **如果你是从零开始，跳过，直接看第八节。**

### 先说一个陷阱

**不要为了搬家而重新整理一遍旧笔记。**

那是最大的坑 —— 你会花两周给几百篇旧笔记分类，
**然后在整理的过程中失去兴趣，库就此停工。**

**正确做法：只搬「还在用的」，其余原封不动当存档。**

### 三步搬法

#### 第一步：全倒进 Inbox（10 分钟）

把旧笔记（微信收藏、备忘录、Notion 导出的 md、Word 文档）**一股脑拖进 `00-收件箱 Inbox/`**。

- **不要改名**
- **不要补 front matter**
- **不要分类**
- 文件名冲突就加个后缀

**为什么**：分类是最耗神的动作，现在做会把你劝退。**先让东西有个家。**

#### 第二步：只挑「这个月用过的」（30 分钟）

翻一遍 Inbox，**只挑出你最近一个月真的翻出来看过的**，移到对应目录。

**其余全部移到 `99-归档 Archive/旧笔记/`。**

> 🔑 **判据：这一个月我有没有主动打开过它？**
> 没有 → 归档。**不是删，是归档** —— 以后想到还能搜到。

**你会发现几百篇里只有几十篇是活的。** 那才是你真正的知识。

#### 第三步：只给"活的"补 front matter（按需）

归档那批**不用补**。活着的那些，**下次打开时顺手补**就行 —— 不要专门坐下来批量补。

### 为什么不一次性整理完

因为**库的价值不在于整齐，在于你还在写。**

一个 300 篇乱糟糟、但每天都在长的库，
比一个 300 篇整整齐齐、但三个月没打开的库，**有用一百倍**。

### 多久算搬完

**永远搬不完，也不需要搬完。**

`99-归档 Archive/旧笔记/` 那堆东西就在那儿，需要时搜一下。
**它们不是负债，是备份。**

## 进阶二：让库跟着你走（多设备同步 · 坚果云）

> 这一节是**选修**。只在一台电脑上写也能用，但"随时能记"才是日记不断的关键。
>
> 📎 **坚果云官方同步教程**：<https://blog.jianguoyun.com/?p=6104>

### 为什么用坚果云

市面上的选择：

| 方案 | 优点 | 缺点 |
|---|---|---|
| **坚果云**（我用的）| 中文、免费额度够用、有成熟的 Obsidian 插件 | 免费版有流量限制 |
| iCloud / OneDrive | 系统自带 | 国内速度不稳；Windows 上体验一般 |
| Syncthing | 完全免费、点对点 | 要自己配，手机端麻烦 |
| **git**（你已经有）| 版本历史完整 | **不能实时同步**，手机上不好用 |

**建议：坚果云管"实时同步"，git 管"历史版本"。两个一起用。**
它们不冲突 —— 一个管多设备，一个管"回到过去"。

### 装什么

**Obsidian 社区插件市场** 搜 **坚果云** 或 **Nutstore**，装 `Nutstore Sync`。

- 插件开源仓库（查更新、报问题）：<https://github.com/nutstore/obsidian-nutstore-sync>
- 社区插件页：<https://community.obsidian.md/plugins/nutstore-sync>
- 坚果云官方同步教程：<https://blog.jianguoyun.com/?p=6104>

> ⚠️ **这不是 Obsidian 官方功能**，是社区插件。所以：**插件更新可能出问题，重要内容一定要有 git 兜底。**

### 装完先确认这 4 项（默认就是对的，别乱动）

这四项关系到"会不会丢东西"。**好消息是：插件的默认值已经是对的** ——
你要做的是**确认它们没被改过**，而不是去改它们：

| 配置（括号里是插件内部键名） | 应该是 | 为什么 |
|---|---|---|
| **删除前确认**（`confirmBeforeDeleteInAutoSync`）| **开**（默认开）| 自动同步时如果云端少了一批文件，可能会连带删本地。**保持开** |
| **同步 `.obsidian` 配置目录** | **关**（默认 `none`）| 多设备各有各的主题、插件、窗口布局。同步它 = 每台设备互相打架 |
| **大文件跳过阈值** | **30 MB**（默认）| 防止一个视频/压缩包撑爆同步额度 |
| **冲突处理** | **无冲突合并**（默认，内部值 `NoConflictMerge`）| 两边都改了同一个文件时，尝试合并成一份，而不是直接覆盖 |

> ⚠️ 顺序很重要：**先确认，再同步。** 首同步之前把这几项对了，比丢东西之后回滚划算得多。

### 过滤规则：这 26 条别删

插件自带 **26 条**排除规则（下表按类归并，完整列表在插件设置里能看到）—— **每一条都有理由**：

| 排除 | 为什么 |
|---|---|
| `.git` / `.svn` / `.github` | **同步 `.git` 会让同步极慢，还可能损坏仓库** |
| `.env` / `.env.*` | 里面可能有密钥，**不要同步到云端** |
| `node_modules` | 几万个文件，同步会卡死 |
| `.claude` / `.codex` / `.cursor` / `.vscode` | 各 IDE 的本地缓存 |
| `.trash` | 回收站，没必要同步 |
| `~$*.docx` 等 | Office 打开文件时生成的临时锁文件 |
| `desktop.ini` / `Thumbs.db` / `.DS_Store` | 系统垃圾 |

> 📌 **判断标准**：**能重新生成的、含密钥的、体积大的 → 排除。**
> 你的笔记是唯一不可再生的东西。

### 它带来的额外好处：库内 AI

坚果云插件**内置了一个 AI 对话窗口**（官方叫 **AI Agent ChatBox**，我平时就叫它 ChatBox）。它和你用 ChatGPT 不一样：

| | 外部 AI（ChatGPT 等）| 库内 AI |
|---|---|---|
| 能看到你的库 | ❌ 要你复制粘贴 | ✅ **直接读整个库** |
| 能改文件 | ❌ | ✅ 能 |
| 有 git | — | ❌ **改完要有人替它提交** |
| 跨对话记忆 | 有 | ➖ **会话能留存，但结论仍应落盘** |

**它最适合干的活**：整理收件箱、给笔记补 front matter、找重复内容、把长文压缩成摘要。

**它干不了的活**：替你提交 git、跑本地脚本。要它联网得你自己配 MCP。

> ⚠️ **结论要落盘，不要只留在对话里。** 新版插件有持续会话和跨会话的 Memory，
> 但会话会被压缩、会被清理 —— **只有写进文件的那一份才靠得住。**

### 三个坑

| 坑 | 表现 | 解法 |
|---|---|---|
| **手机首次同步很慢** | 几百个文件要传很久 | 第一次让它挂着传完，别中途关 Obsidian |
| **`.obsidian` 不同步的副作用** | 换设备要重装插件、重设主题 | 接受它。**这比多设备配置互相覆盖好得多** |
| **同时改同一个文件** | 生成 `xxx.conflict.md` | 看到就手动合并。**别两个设备同时编辑同一篇** |

## 十、文件说明

### 两个 skill + 三份零件

```
distill-myself/
├── README.md                    ← 【说明书】你现在读的这份
├── skills/                      ← 【可安装】给 AI 执行
│   ├── obsidian-second-brain/
│   │   └── SKILL.md             帮你搭这个库
│   └── life-archive/
│       ├── SKILL.md             帮你把过去整理成人生档案
│       └── agents/openai.yaml   给 OpenAI 系工具用的界面配置
├── templates/                   ← 【零件】直接复制进你自己的库
│   ├── 笔记模板.md
│   ├── 日记模板.md
│   └── 资料模板.md
└── boilerplate/                 ← 【零件】改一改当自己的规则
    ├── README.md
    └── AGENTS.md
```

### 每个是干什么的

| 文件 | 是什么 | 怎么用 |
|---|---|---|
| **`README.md`** | **说明书** —— 讲这套方法怎么做的 | 读它。**你正在看的就是这份** |
| **`skills/obsidian-second-brain/`** | **搭库的 skill** —— 装进 AI 工具后，一句话就能让 AI 带你搭 | 放进 skills 目录（见下）|
| **`skills/life-archive/`** | **人生档案的 skill** —— 逐轮访谈，把讲出来的过去整理成可核实的档案 | 同上 |
| **`templates/笔记模板.md`** | 通用笔记的空壳（只有 front matter 骨架） | **直接复制**进你库的 `90-模板 Templates/` |
| **`templates/日记模板.md`** | 日记模板，四节（含「和 AI 聊完之后的总结」） | **直接复制**进你库的 `90-模板 Templates/` |
| **`templates/资料模板.md`** | 外部资料模板（来源 / 核心内容 / 我的判断 / 关联） | **直接复制**进你库的 `90-模板 Templates/` |
| **`boilerplate/README.md`** | **你要放进自己库里那份 README 的模板** | 挪到库根目录，改名 `README.md`，改三处 |
| **`boilerplate/AGENTS.md`** | **给 AI 的规矩的模板** | 挪到库根目录，改名 `AGENTS.md`，改三处 |

### 两个 skill 的分工

| | `obsidian-second-brain` | `life-archive` |
|---|---|---|
| 管什么 | **往后** —— 从今天开始记 | **往回** —— 把过去理出来 |
| 输入 | 你零散的想法 | 你讲的人生片段 |
| 输出 | 一套能用的目录和规则 | 分阶段的人生档案 |
| 适合谁 | 想搭第二大脑、但笔记越记越乱 | 想回顾人生、又不想写作文 |

**它们是同一件事的两端：都把「散的东西」蒸馏成「有结构的档案」。**

> 📌 `life-archive` 最值得学的一点：它**先不让你读指南、填问卷、建目录** ——
> 只问「你脑海里最先浮现的是哪个画面？」。**门槛降到这一步，人才讲得出来。**

> ⚠️ **`life-archive` 会涉及隐私**。它的规则里写了：文件名不用真实姓名和学校全名、
> 默认 `privacy: 私密`、公开分享要先做脱敏副本。
> **但 `privacy` 只是个标签，不是加密** —— 别把真正的隐私内容推到公开仓库。

### ⚠️ 最容易搞混的：有两个 `README.md`

| | 根目录的 `README.md` | `boilerplate/README.md` |
|---|---|---|
| 是什么 | **说明书** —— 教你怎么搭 | **零件** —— 搭完之后放进你库里的那份 |
| 要不要改 | 不用改 | **必须改**（改成本人是谁、有哪些 Areas）|
| 放哪 | 留在这个仓库里 | **复制进你自己的 Obsidian 库** |

> **一句话分清**：根目录那份讲「**怎么搭**」，`boilerplate/` 那份是「**搭完之后你的库长什么样**」。

### 三个模板要改吗

**不用改，直接复制。** 里面只有 front matter 和标题空壳。

唯一看着奇怪的是 `{{date:YYYY-MM-DD}}` —— 那是 Obsidian 模板语法，在 Obsidian 里用会自动填成当天日期。
用记事本打开会看到原样占位符，**那是正常的**。

### 怎么用 skill

把 `skills/` 里**整个 skill 目录**（是那一层文件夹，不是里面的 SKILL.md）放进你的 AI 工具的 skills 目录：

- **WorkBuddy**：`~/.workbuddy/skills/`
- **Claude Code**：`~/.claude/skills/`

装完跟 AI 说：

> **想搭库** →「用 obsidian-second-brain 这个 skill 帮我搭一个第二大脑」
>
> **想整理过去** →「用 life-archive 这个 skill，陪我从一个记得的片段开始整理人生档案」

第一个会带你走完第八节那七步；第二个会一轮问一个问题，边聊边整理成 Markdown。

> 📌 **两个 skill 分工不同，别混用**：
> 一个管「**往后**」（从今天开始记），一个管「**往回**」（把过去理出来）。
> 同时用也没问题，它们不抢文件。

> ⚠️ **`life-archive` 的产出请放私有库。** 它写的是你的人生经历 ——
> 里面可能有家人的事、你不想公开的片段。
> **这个仓库只放方法，不放你的档案。** 它自己也写了：`privacy: 私密` 只是个标签，不是加密。

> 💡 **skill 和 README 的区别**：
> README 是给**人**读的（讲清楚为什么这么做），skill 是给 **AI 执行**的（只讲做什么、怎么验收）。
> 内容有重叠，但一份能读、一份能跑。

做这个库最大的收获不是"有了一个知识库"。

**这件事不需要天赋，只需要每天都做一点点。**
