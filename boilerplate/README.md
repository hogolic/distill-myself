# 我的知识库 · 使用说明

<!-- 改成你自己的。这份文件的作用：让别人（和 AI）30 秒看懂这个库怎么用。 -->

（一句话说清这个库是什么）
例：某某的个人知识库。纯 Markdown 文件夹，用 Obsidian 打开即可。

> 📌 **规则只有两份：本文件 + `AGENTS.md`。**
> 本文件讲「这个库是什么、东西放哪、笔记怎么写」；`AGENTS.md` 讲「干活要守什么规矩」。

---

## 🔴 唯一一条铁律：能增、能改、能移，**不能删**

**可以增加文件、修改文件、移动文件 —— 但不能删除文件。**

要"删掉"的东西一律 **移到 `99-归档 Archive/`**。

> **为什么**：增、改、移都能回滚（git 有记录），**删除不能**。
> 尤其收件箱里那些还没被提交过的草稿，删掉就是永久消失。

## 目录结构（PARA 变体）

| 目录 | 放什么 |
|---|---|
| `00-收件箱 Inbox/` | 临时想法、待处理材料。不确定放哪的，先扔这儿 |
| `10-项目 Projects/` | 正在推进的项目 —— **有明确终点**，做完就结项 |
| `20-领域 Areas/` | 需要长期维护的领域 —— **没有终点**，要一直维持 |
| `30-知识 Knowledge/` | 经过理解、整理过的知识 |
| `40-日记 Journal/` | 日记、每日记录、阶段性反思 |
| `90-模板 Templates/` | 模板文件，不写内容 |
| `91-附件 Attachments/` | 图片、PDF 等附件 |
| `99-归档 Archive/` | 已结束或暂停的内容。不删，但不再推进 |

### Projects 和 Areas 怎么分？

PARA 唯一需要动脑的地方，判据只有一条：**有没有终点。**

- 「做一个抽帧工具」→ 有终点 → **Projects**
- 「英语」「技术能力」「身体与健身」→ 没有终点 → **Areas**
- 「备考某场考试」→ 考完就结束 → **Projects**（但它**服务于**「英语」这个 Areas）

**Projects 可以结束，Areas 不会。**

### Knowledge 和 Areas 的区别

- 「高位下拉宽握更偏向背阔肌外侧」→ 一个知识点 → **Knowledge**
- 「英语」→ 要长期维持的领域 → **Areas**

Knowledge 是**你学明白了什么**，Areas 是**你在持续维护什么**。

**原则**：Inbox 允许乱，其他目录必须整洁。乱的东西只准待在 Inbox。

## 每篇笔记的开头必须写 front matter

front matter 是文件最顶上用 `---` 包起来的一小段信息，就是**给笔记贴的标签**，
让搜索功能、以及半年后的你自己，知道这篇笔记叫什么、从哪来、什么时候写的。

```markdown
---
title: 高位下拉的握距区别
tags: [健身, 背部, 动作细节]
source: 
created: 2026-10-16
status: 已整理
---

正文从这里开始……
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 一句话说清这篇讲什么 |
| `tags` | ✅ | 2-5 个，别超过 5 个，否则等于没打 |
| `source` | ➖ | 外部资料必填（网址/书名/课程名）；自己写的留空 |
| `created` | ✅ | 创建日期 `YYYY-MM-DD` |
| `status` | ✅ | `草稿` / `待核对` / `已整理` 三选一 |

**只需要复制模板改内容，不用记。** 模板在 `90-模板 Templates/`。

## 文件命名

- 笔记：直接用中文标题，例如 `高位下拉的握距区别.md`
- 日记：`2026-10-16.md`（固定格式，方便按时间翻）
- 外部资料：`标题 - 来源.md`
- ❌ 不要用 `新建笔记1.md`、`未命名.md` 这种名字

---

## 日常工作流

1. **随时**：有话往 `00-收件箱 Inbox/` 扔，文件名随便起，不写 front matter 也行
2. **每天**：`40-日记 Journal/` 里今天那篇写几行
3. **每周**：把 Inbox 里值得留的补上 front matter，归到 Projects / Areas / Knowledge
4. **项目结束**：移到 `99-归档 Archive/`，不要删 —— 以后回顾时它是素材

## 双链怎么用

笔记里写 `[[另一篇笔记的名字]]` 就能链过去。如果那篇还不存在，
Obsidian 会把它显示成**未解析链接**（颜色浅一点）。

**这不是报错，是待办清单。** 点一下就建好了。

> ⚠️ **但别一次建几十个空链接。** 那是"看起来有结构"，不是真有结构。
> 要写就从里面挑一个真想的，写满一页。

## 提交与查历史

**看谁在什么时候改了什么 → `git log`：**

```bash
git log --oneline                    # 一句话一条
git log -1 --stat                    # 最近一次改了哪些文件
git log --since="3 days ago" --stat  # 最近三天的
```

**大改动（重构目录、批量移动）先写清楚"要动什么、为什么"再执行。**

## 环境（已就绪）

- **Obsidian**，仓库指向（你的路径）
- **附件** → `91-附件 Attachments`
- **模板** → `90-模板 Templates`
- **日记** → `40-日记 Journal/`，文件名格式 `YYYY-MM-DD`
- **git** 已初始化

### ⚠️ 两个已知的「假改动」，别每次都去查

1. **行尾差异**：如果你的库装了 `.gitattributes` 并写了 `* -text`，diff 会按字节比较。如果 diff 看起来整篇都变了，先怀疑行尾 ——
   去掉 `\r` 后内容一致，就说明根本没变
2. **Obsidian 重排表格**：在 Obsidian 里打开含表格的笔记，它**可能给列补空格对齐**，产生一份内容完全等价的 diff。
   **这是工具的正常行为，看到了直接提交**

> 判据统一：**去掉空白字符后内容一致 → 就是格式噪音，放心提交。**
